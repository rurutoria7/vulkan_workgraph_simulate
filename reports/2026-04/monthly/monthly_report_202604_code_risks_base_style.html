Persistent Thread Model

Workgroup Role Queue Action
WG 0 Node A + B Seed → Q1 Thread 0 seeds 3 edges, then all do Node B
WG 1–71 Node B Q1 → Q1 / Q2 Pop Q1, subdivide, push back Q1 or forward Q2
WG 72–95 Node C Q2 → VB Pop Q2, write vertices, count → stopFlag
Single dispatch: vkCmdDispatch(96, 1, 1) = 96 WG × 32 threads = 3,072 persistent threads
Shader Main Loop Structure:
void main() {
    uint wgId = gl_WorkGroupID.x;
    uint localId = gl_LocalInvocationID.x;
    // Node A: WG 0, Thread 0 seeds 3 edges (once)
    if (wgId == 0 && localId == 0) {
        if (atomicCompSwap(control.seedDone, 0, 1) == 0)
            pushQ1(edge_AB); pushQ1(edge_BC); pushQ1(edge_CA);
    }
    barrier(); memoryBarrierBuffer();
    // Main persistent loop
    while (control.stopFlag == 0) {
        if (wgId < NODE_C_START) { /* Node B */ }
        else                     { /* Node C */ }
    }
}

Atomic Queue Mechanism

Ring Buffer Structure

QueueControl: head / tail / count

Task: payload[6] (4×float + depth + ready)

Push Protocol:

  1. CAS count (reserve slot)
  2. atomicAdd tail (get slot index)
  3. Write payload[0–4]
  4. memoryBarrierBuffer()
  5. atomicExchange(ready, 1)

Pop Protocol:

  1. CAS count (claim item)
  2. atomicAdd head (get slot)
  3. Spin: atomicCompSwap(ready,1,0)
  4. Read payload
pushQ1() Implementation:
bool pushQ1(uint p0, uint p1, uint p2,
            uint p3, uint p4) {
  while (control.stopFlag == 0) {
    uint cur = control.q1.count;
    if (cur < QUEUE_SIZE) {
      // CAS: reserve a slot
      if (atomicCompSwap(control.q1.count,
                         cur, cur+1) == cur) {
        uint slot = atomicAdd(
          control.q1.tail, 1) % QUEUE_SIZE;
        // Write payload
        queue1.tasks[slot].payload[0] = p0;
        queue1.tasks[slot].payload[1] = p1;
        queue1.tasks[slot].payload[2] = p2;
        queue1.tasks[slot].payload[3] = p3;
        queue1.tasks[slot].payload[4] = p4;
        memoryBarrierBuffer();
        // Signal ready (atomic!)
        atomicExchange(
          queue1.tasks[slot].payload[5], 1u);
        return true;
      }
    }
  }
  return false;
}

Cross-Workgroup Memory Sync

Bug 1

Missing coherent modifier

Node C read stale count from L0/L1 cache → no task consumption

Fix: Added coherent to all SSBO declarations
Bug 2

Producer-consumer data race

Producer increments count then writes data; consumer reads uninitialized

Fix: Added per-slot payload[5] ready flag protocol
Bug 3

Plain store cross-CU unreliable

Plain store of ready flag not visible across CUs

Fix: All ready flags use atomicExchange / atomicCompSwap
Memory Visibility:
Method Same WF Same CU Cross-CU
Plain load/store ✔ ~ ✘
coherent ✔ ✔ ~
Atomic (CAS/Exch) ✔ ✔ ✔

Takeaway

Cross-CU queue state needs atomic publish/consume; coherent alone is not enough.

Koch Snowflake Algorithm

Subdivision Rule:

Each edge P1→P2 splits into 4 sub-edges: P1 → A → C → B → P2 A, B = 1/3, 2/3 points along P1P2 C = apex point, rotated +60° from A Growth: 3 × 4^depth edges depth=4: 768 edges (1,536 vertices) depth=6: 12,288 edges (24,576 vertices)

Node B: Subdivision Core:
// Koch subdivision: 1 edge -> 4 sub-edges
float dx = (x2 - x1) / 3.0;
float dy = (y2 - y1) / 3.0;
// A = 1/3 point, B = 2/3 point
float kax = x1 + dx,   kay = y1 + dy;
float kbx = x1 + 2*dx, kby = y1 + 2*dy;
// C = apex (rotate +60° from A)
float cos60 = 0.5;
float sin60 = 0.8660254037844387;
float kcx = kax + dx*cos60 - dy*sin60;
float kcy = kay + dx*sin60 + dy*cos60;
// Push 4 sub-edges (depth+1)
pushQ1(P1→A); pushQ1(A→C);
pushQ1(C→B);  pushQ1(B→P2);
GPU Self-Termination:
// Node C: auto-shutdown when all edges processed
uint processed = atomicAdd(control.totalProcessed, 1) + 1;
if (processed >= MAX_DEPTH_EDGES) {
    atomicExchange(control.stopFlag, 1u);  // all threads exit
}

Per-frame pipeline

Code evidence: reset, compute, barrier, and render are serialized in one command buffer.

workgraph_poc.cpp:267-322

vkCmdFillBuffer(cmd, compute.controlBuf, ...);
vkCmdFillBuffer(cmd, compute.q1Buf, ...);
vkCmdFillBuffer(cmd, compute.q2Buf, ...);

vkCmdPipelineBarrier(... TRANSFER -> COMPUTE ...);
vkCmdDispatch(cmd, NUM_WORKGROUPS, 1, 1);

vkCmdPipelineBarrier(... COMPUTE -> VERTEX_INPUT ...);
vkCmdDraw(cmd, EXPECTED_VERTICES, 1, 0, 0);

What it does

A deterministic per-frame baseline: reset, persistent compute, sync, then fixed-count rendering.

Risk

Profiler-friendly, but not necessarily optimal. It does not test async compute / graphics overlap.

Possible fix

Keep as correctness baseline; later split compute/gfx scheduling or reduce synchronization scope.

GPU-side termination

Code evidence: completion is decided by Node C using a global processed-edge counter.

headless.comp:153-160

uint base = atomicAdd(control.vertexCount, 2);
output_vb.vertices[base]     = vec2(x1, y1);
output_vb.vertices[base + 1] = vec2(x2, y2);

uint processed = atomicAdd(control.totalProcessed, 1) + 1;
if (processed >= MAX_DEPTH_EDGES) {
    atomicExchange(control.stopFlag, 1u);
}

What it does

No CPU polling. The GPU terminates itself after the expected number of output edges.

Risk

Count-only termination can fail if MAX_DEPTH_EDGES or workload shape is wrong.

Possible fix

Add queue-drain or in-flight accounting as a second termination condition.

Risk

Fixed-size backing queues

Code evidence: queue capacity is fixed and producers spin when no slot is available.

workgraph_poc.cpp:8, headless.comp:29-45

#define QUEUE_SIZE 16384

bool pushQ1(...) {
    while (control.stopFlag == 0) {
        uint cur = control.q1.count;
        if (cur < QUEUE_SIZE) {
            if (atomicCompSwap(control.q1.count, cur, cur + 1) == cur) {
                uint slot = atomicAdd(control.q1.tail, 1) % QUEUE_SIZE;
                ...
            }
        }
    }
}

What it does

A global ring buffer backs cross-workgroup producer-consumer handoff.

Risk

Too small increases retries and progress risk; too large increases memory footprint and locality pressure.

Possible fix

Define sizing from worst-case frontier growth plus safety margin; add pressure counters later.

Atomic queue handoff

Code evidence: ready flag publishes a slot only after payload writes are visible.

headless.comp:33-41, 97-101

// Producer
atomicCompSwap(control.q1.count, cur, cur + 1);
uint slot = atomicAdd(control.q1.tail, 1) % QUEUE_SIZE;
queue1.tasks[slot].payload[0] = p0;
...
memoryBarrierBuffer();
atomicExchange(queue1.tasks[slot].payload[5], 1u);

// Consumer
while (atomicCompSwap(queue1.tasks[slot].payload[5], 1u, 0u) != 1u) { ... }

What it does

Correctness relies on atomics plus per-slot publish/consume protocol.

Risk

Global counters and ready flags can become contention hotspots as worker count scales.

Possible fix

Reduce global atomic pressure with batching, per-WG staging, or LDS/local queues.

Spin wait risk

Code evidence: consumers busy-spin on ready flags; cost is identified but not measured in this report.

headless.comp:99-101, 143-145

// Q1 consumer waits for producer publish
while (atomicCompSwap(queue1.tasks[slot].payload[5], 1u, 0u) != 1u) {
    if (control.stopFlag != 0u) return;
}

// Q2 uses the same ready-flag spin protocol
while (atomicCompSwap(queue2.tasks[slot].payload[5], 1u, 0u) != 1u) {
    if (control.stopFlag != 0u) return;
}

What it does

Busy-spin is part of the current correctness-first queue handoff design.

Risk

Under producer-consumer imbalance, retries may reduce effective throughput before arithmetic saturates.

Possible fix

Do not claim measured cost yet; later evaluate backoff, role switching, and shorter handoff windows.
